# 사용 가이드

## 1. 데이터셋 준비

- 캐릭터/인물: 15~40장, 다양한 각도·표정·조명·배경. 얼굴이 작게 나온 사진만 있으면 학습이 어렵습니다.
- 스타일: 30~100장, 주제는 다양하게 하고 화풍만 일관되게.
- 해상도: 짧은 변 1024px 이상 권장 (작은 이미지는 확대되어 흐려짐).
- 캡션: `이미지이름.txt`. 트리거 단어 위치를 정하고 싶으면 캡션에 `[trigger]` 를 쓰세요.
  - 캐릭터: "학습시키고 싶은 특징은 쓰지 말고, 바뀌어도 되는 것(옷, 배경, 포즈)은 쓴다"
  - 스타일: 장면 내용은 자세히, 화풍 표현은 트리거에 맡기기

### MOSS-Image 자동 캡션 (공식 가이드 형식 · Ollama Gemma 4)

[MOSS-Image 공식 가이드](https://github.com/OpenMOSS/MOSS-Image/blob/main/USERGUIDE.md#image-captioning) 의 리캡션 방식을 그대로 따릅니다.

1. [Ollama](https://ollama.com) 설치 후 Gemma 4 비전 모델 받기 — 명령 프롬프트에서
   `ollama pull gemma4:e4b` (VRAM 12GB 이하 권장) 또는 `ollama pull gemma4:26b` (24GB 이상)
2. **설정 → MOSS-Image 캡션 · Ollama** 에서 주소(기본 `http://localhost:11434`)와 모델 선택 → *연결 테스트*
   - 공식 권장값: thinking 켬 · temperature 1.0 · top_p 0.95 · 최대 16384 토큰 (*공식 권장값* 버튼)
3. 베이스 모델을 MOSS-Image 로 둔 상태에서 **데이터셋 → 자동 캡션 생성 (MOSS 공식 형식)**
   - 대화상자에서 Gemma 4 모델을 바꿀 수 있고, *이 모델을 기본값으로 저장* 으로 설정에 반영
   - 작업 범위: **없는 것 새로 + 다른 형식은 공식 형식으로 다시** (기본) / 없는 것만 / 전부 다시

저장 형식 (이미지 `img001.png` 기준)

| 파일 | 내용 |
|---|---|
| `img001.moss.json` | 공식 형식 원본: `caption.long / medium / short`, `watermark[{box_2d, label}]`, `borders` |
| `img001.txt` | 학습에 쓰는 캡션 = 선택한 변형 (기본 long). 편집기 아래 `long / medium / short` 버튼으로 이미지별 전환 |

썸네일 표시: `✓` 공식 형식 · `⚠` 캡션 없음 · `◇` 다른 형식(태그·짧은 문장 등 → 다시 생성 대상) · `✎` 직접 수정함(보존)

- 기존 캡션은 공식 가이드처럼 *reference* 로 넘겨 참고만 하고, 이미지와 다르면 고칩니다.
- 덮어쓰기 전 기존 `.txt` / `.moss.json` 은 `<폴더>/_caption_backup/<시각>/` 에 백업됩니다.
- 트리거 단어는 캡션에서 빼고 넘기며, 학습 때 자동으로 앞에 붙습니다.
- 워터마크 글자는 캡션에 넣지 않고 `watermark` 에 위치만 기록합니다.
- 캡션이 끝나면 Ollama 모델을 VRAM 에서 내려 학습 VRAM 을 확보합니다 (설정에서 끌 수 있음).

## 2. 모델 파일

경로를 비우면 아래 기본값을 자동으로 받습니다 (`설정 > 모델 다운로드 폴더`).

| 모델 | 구성 | 기본 경로 |
|---|---|---|
| Krea 2 | DiT | `krea/Krea-2-Raw/raw.safetensors` (게이트, 토큰 필요) |
| | 텍스트 인코더 | `Qwen/Qwen3-VL-4B-Instruct` |
| | VAE | `Qwen/Qwen-Image::vae` (폴더 · 단일 파일 · ComfyUI `qwen_image_vae.safetensors` 모두 가능) |
| MOSS-Image | DiT | `Comfy-Org/MOSS-Image/diffusion_models/moss_image_base_bf16.safetensors` |
| | 텍스트 인코더 | `Qwen/Qwen3.5-9B` |
| | 토크나이저 | `OpenMOSS-Team/MOSS-Image-Base::tokenizer` |
| | VAE | `Comfy-Org/MOSS-Image/vae/flux2-vae.safetensors` |

- ComfyUI 에 있는 파일도 지정 가능 (ComfyUI scaled-fp8 체크포인트는 자동 역양자화되지만, 학습 품질을 위해 bf16 원본 권장).
- MOSS 공식 diffusers 폴더(`transformer/` 샤드)도 지정 가능 — q/k/v 를 자동으로 결합합니다.

## 3. 주요 설정 감 잡기

| 항목 | 캐릭터 | 스타일 |
|---|---|---|
| rank / alpha | 32 / 32 | 16 / 16 |
| 학습률 (AdamW8bit) | 1e-4 | Krea 2 1e-4 · MOSS 5e-5 |
| 스텝 (이미지 25장 기준) | 1500~2500 | 2500~4000 |
| 적용 레이어 | Krea 2: 모든 Linear(264개) · MOSS: 어텐션+MLP(42블록) | 같음 |
| EMA 평균 | 0.98 | Krea 2 0.98 · MOSS 끔 |
| 깨끗한 쪽 비율 (MOSS) | 60% | 60% (구도가 사진에 붙으면 30%) |

- 샘플(미리보기): Krea 2 는 **Turbo LoRA 빠른 미리보기**(샘플 페이지, 프리셋 기본 켬)로 약 4배 빠르게 확인할 수 있습니다. MOSS-Image 는 res_multistep 30스텝 · CFG 4 로 ComfyUI 와 같은 결과를 냅니다.
- 위 값은 Fizgig(v8.7.0)의 Krea 2 · MOSS-Image 프리셋을 기준으로 맞췄습니다.
- MOSS-Image 는 수렴이 느립니다. 닮음이 멈춘 것 같아도 후반 체크포인트가 더 좋은 경우가 많으니 마지막 몇 개를 비교하세요.

- 과적합 신호: 샘플이 데이터셋 사진을 그대로 복제, 트리거 없는 프롬프트도 같은 얼굴 → 이전 체크포인트 사용 또는 스텝/학습률 줄이기
- 미적합 신호: 트리거를 넣어도 변화가 적음 → 스텝 늘리기, 학습률 소폭 올리기
- loss 값 자체는 노이즈가 커서 절대값보다 **샘플**로 판단하세요.

## 4. 학습 중 조작

- **일시정지/재개**: 현재 스텝이 끝나면 멈춥니다 (GPU 메모리는 유지).
- **지금 샘플 / 지금 저장**: 다음 스텝 후 바로 실행.
- **중지**: 현재까지의 LoRA 를 `_interrupted` 로 저장하고 종료.
- **이어학습**: 학습 설정 → 이어학습에 `output/<이름>/state` 지정 후 시작 (총 스텝을 더 크게).

## 5. 문제 해결

| 증상 | 해결 |
|---|---|
| CUDA out of memory | 해상도 768, 샘플 크기/스텝 축소, 텍스트 인코더 NF4, (Krea) DiT NF4 |
| 401/403 다운로드 오류 | 허깅페이스 토큰 확인, Krea 2 라이선스 동의 여부 |
| loss NaN | 학습률 낮추기, fp16 대신 bf16 (RTX 30 이상) |
| 너무 느림 | 블록 스왑 끄기, 샘플 주기 늘리기, 그래디언트 체크포인팅은 VRAM 여유 있을 때만 끄기 |
| Qwen3.5/Qwen3-VL 로딩 오류 | `venv\Scripts\pip install -U transformers` |

설정 페이지의 **환경 점검** 버튼으로 PyTorch/CUDA/패키지 상태를 확인할 수 있습니다.

## 6. 시스템 맞춤 추천 (시작하기)

- 데이터셋 폴더를 먼저 추가한 뒤 시작하기 페이지의 **시스템 맞춤 추천 설정**을 보세요. 학습 목적(캐릭터/스타일/범용)을 고르면 다시 계산됩니다.
- **퀄리티 중시**: 가능한 가장 높은 정밀도(필요하면 블록 스왑), 멀티 해상도, rank 상향, 스텝 +30%
- **최적 (권장)**: 블록 스왑 없이 들어가는 가장 높은 정밀도, 기본 해상도
- **속도 중시**: 768 해상도, 스텝 -25%, VRAM 여유가 있으면 체크포인팅 끔
- 적용하면 정밀도·해상도·rank·옵티마이저·학습률·스텝·저장/샘플 간격이 바뀌고, 이름·데이터셋·모델 경로·프롬프트는 그대로입니다.
- 예상 시간은 GPU 성능표 기반 근사치입니다. 학습을 한 번 끝내면 실측 속도로 보정되어 카드에 "실측 보정 N회" 로 표시됩니다.

## 7. 대기열 (여러 LoRA 연속 학습)

1. 첫 번째 LoRA 를 평소처럼 설정합니다 (모델·학습 설정·샘플).
2. 시작하기의 **+ 대기열에 추가** (또는 대기열 페이지의 **+ 현재 설정으로 추가**) → LoRA 이름과 데이터셋 이미지 폴더만 입력. 캐릭터마다 다르면 트리거 단어도 입력.
3. 필요한 만큼 반복한 뒤 대기열 페이지에서 **▶ 대기열 시작**. 위에서부터 하나씩 학습합니다.

- 각 항목은 추가한 순간의 설정을 저장합니다. 이후 화면 설정을 바꿔도 이미 예약된 항목은 바뀌지 않습니다.
- 진행 중 **중지**를 누르면 "이 항목만 중지(다음 진행)" / "대기열 전체 중지" 를 고를 수 있습니다.
- 대기열은 `user_data/queue/` 에 저장되어 프로그램을 다시 켜도 유지됩니다 (진행 중 종료된 항목은 '중지됨' → 우클릭 '다시 대기').

## 8. 모델 페이지 — 모델별 파일

- 맨 위에서 **Krea 2 / MOSS-Image** 중 지금 설정할 모델을 고릅니다 (시작하기의 선택과 연동).
- 모델마다 경로가 따로 저장되므로 모델을 바꿔도 다른 모델의 경로가 섞이지 않습니다.
- 각 칸 아래 상태: ✓ 확인됨 · ⬇ 자동 다운로드 · ✗ 없음 · ⚠ 다른 모델용 파일
- **폴더에서 자동 찾기**: ComfyUI `models` 폴더 등을 고르면 그 모델에 맞는 파일을 찾아 제안합니다.
- 사이드바 하단에서 CPU / RAM / GPU / VRAM 사용량을 실시간으로 볼 수 있습니다 (GPU 사용률은 `nvidia-ml-py` 필요).
