# 코드 구조

## 전체 흐름

```
GUI (PySide6)                       학습 프로세스 (별도 python)
 ├ 페이지에서 설정 입력              lora_trainer.train.runner
 ├ job.yaml 저장  ───────────────▶   Trainer.run()
 ├ QProcess 로 실행                   1. 데이터셋 스캔 / 버킷
 │                                    2. 텍스트 임베딩 캐시 (TE 만 GPU)
 │  ◀── stdout "@@EVENT {json}" ──    3. latent 캐시 (VAE 만 GPU)
 ├ 진행률/loss/샘플 표시              4. DiT 로딩 (FP8/NF4/블록스왑) + LoRA 주입
 └ 제어 파일(.stop/.pause 등) 생성 ─▶ 5. 학습 루프 · 저장 · 샘플
```

학습을 별도 프로세스로 돌리기 때문에 GUI 가 멈추지 않고, 중지 시 GPU 메모리가 확실히 반환됩니다.

## 학습 수식 (Flow Matching)

- `t ∈ (0,1)`, `t=1` 이 순수 노이즈. `x_t = (1-t)·x0 + t·ε`, 목표 `v = ε - x0`, 손실 `MSE(model(x_t, t), v)`
- Krea 2: `t` 는 로짓-정규 샘플 후 `exp(μ)` 시간이동, `μ` 는 이미지 토큰 수에 따라 0.5(256px) ~ 1.15(1280px) 선형 보간 (공식 샘플러와 동일 규칙)
- MOSS-Image: 모델 입력 timestep = `t × 1000`. 자동 모드는 공식 사전학습 마지막 구간 분포(잘린 로짓-정규, μ -1.09, s 0.95, 1% 균등, 1000 격자)에서 중심만 옮겨 sigma<0.5 비율을 `clean_share`(기본 60%)로 맞춤 (샘플링은 공식 shift 5)
- 미리보기: Krea 2 는 Turbo LoRA(`network/extra_lora.py`)를 샘플 동안만 덧붙여 10스텝 · CFG 1 · mu 1.15, MOSS 는 res_multistep · simple(shift 5) · CFG 4
- EMA: 학습은 원래 가중치, 저장 · 샘플은 `ema_decay`(기본 0.98) 평균 가중치 (`network/ema.py`)
